[209. Minimum Size Subarray Sum](https://leetcode.com/problems/minimum-size-subarray-sum/description/?envType=study-plan-v2&envId=top-interview-150) (Medium)
---

### Core Insight
Use a **sliding window** — expand right, shrink left whenever the window sum meets `target`. Track the minimum window length throughout.

---

### O(n) — Sliding Window

```csharp
public int MinSubArrayLen(int target, int[] nums) {
    int left = 0, sum = 0, minLen = int.MaxValue;

    for (int right = 0; right < nums.Length; right++) {
        sum += nums[right];

        while (sum >= target) {
            minLen = Math.Min(minLen, right - left + 1);
            sum -= nums[left++];  // shrink from left
        }
    }

    return minLen == int.MaxValue ? 0 : minLen;
}
```

**Why it works:** Every element is added once and removed at most once → **O(n)** time, **O(1)** space.

---

### O(n log n) — Prefix Sums + Binary Search

```csharp
public int MinSubArrayLen(int target, int[] nums) {
    int n = nums.Length;
    int[] prefix = new int[n + 1]; // prefix[i] = sum of nums[0..i-1]

    for (int i = 1; i <= n; i++)
        prefix[i] = prefix[i - 1] + nums[i - 1];

    int minLen = int.MaxValue;

    for (int i = 0; i < n; i++) {
        int needed = target + prefix[i]; // find j where prefix[j] >= needed
        int lo = i + 1, hi = n;

        while (lo <= hi) {             // binary search on sorted prefix array
            int mid = lo + (hi - lo) / 2;
            if (prefix[mid] >= needed) {
                minLen = Math.Min(minLen, mid - i);
                hi = mid - 1;          // try to find a shorter window
            } else {
                lo = mid + 1;
            }
        }
    }

    return minLen == int.MaxValue ? 0 : minLen;
}
```

**Why it works:** Prefix sums are strictly increasing (all `nums[i] >= 1`), so binary search is valid. **O(n log n)** time, **O(n)** space.

---

### Complexity Comparison

| Approach | Time | Space | Use When |
|---|---|---|---|
| Sliding Window | O(n) | O(1) | Always preferred |
| Prefix + Binary Search | O(n log n) | O(n) | Asked explicitly, or values can be negative |

---

### Key Takeaways
- **Sliding window dominates** — optimal in both time and space for this problem
- **Binary search approach** is valid here only because all values are positive → prefix array is **monotonically increasing**
- Both approaches handle the "no valid subarray" case by checking if `minLen` was ever updated
- `int.MaxValue` as the initial sentinel avoids needing a separate boolean flag

## Why Sliding Window is O(n)

The intuition: **each element is touched at most twice** — once by `right`, once by `left`. Never more.

---

### Tracing the Two Pointers

Think of `left` and `right` as two independent cursors, each only **moving forward**:

```
nums = [2, 3, 1, 2, 4, 3]
        ↑
      left=0, right starts here and walks right →
```

- `right` makes **one full pass** across the array: `n` steps
- `left` also makes **at most one full pass**: it can never overtake `right`, so at most `n` steps

**Total moves = n (right) + n (left) = 2n → O(n)**

---

### The Common Misconception

> *"There's a while loop inside a for loop — isn't that O(n²)?"*

That's the trap. Nested loops are **not automatically O(n²)**. What matters is the **total number of iterations across all loop executions**, not the nesting.

Ask yourself: *how many times can `left++` execute across the entire run?*

```csharp
for (int right = 0; right < nums.Length; right++) {  // runs exactly n times
    sum += nums[right];

    while (sum >= target) {
        minLen = Math.Min(minLen, right - left + 1);
        sum -= nums[left++];  // ← left can only increment n times TOTAL
    }
}
```

`left` starts at `0` and can reach at most `n`. It **never resets, never goes backward**. So the `while` body can fire at most `n` times **in total across all iterations of the for loop** — not `n` times per iteration.

### Concrete Walkthrough

```
target = 7, nums = [2, 3, 1, 2, 4, 3]
indices:             0  1  2  3  4  5
```

| Step | right | left | window | sum | Action |
|------|-------|------|--------|-----|--------|
| 1 | 0 | 0 | [2] | 2 | sum < 7, expand |
| 2 | 1 | 0 | [2,3] | 5 | sum < 7, expand |
| 3 | 2 | 0 | [2,3,1] | 6 | sum < 7, expand |
| 4 | 3 | 0 | [2,3,1,2] | 8 | sum ≥ 7 ✓ minLen=4, shrink |
| 5 | 3 | 1 | [3,1,2] | 6 | sum < 7, stop shrinking |
| 6 | 4 | 1 | [3,1,2,4] | 10 | sum ≥ 7 ✓ minLen=4, shrink |
| 7 | 4 | 2 | [1,2,4] | 7 | sum ≥ 7 ✓ minLen=3, shrink |
| 8 | 4 | 3 | [2,4] | 6 | sum < 7, stop shrinking |
| 9 | 5 | 3 | [2,4,3] | 9 | sum ≥ 7 ✓ minLen=3, shrink |
| 10 | 5 | 4 | [4,3] | 7 | sum ≥ 7 ✓ **minLen=2**, shrink |

**Count `right` moves:** 0→1→2→3→4→5 = **6 moves**
**Count `left` moves:** 0→1→2→3→4→5 = **6 moves**
**Total = 12 operations for n=6. Scales as 2n, not n².**

---

### The General Rule to Remember

> **Any algorithm where each element is added once and removed once is O(n)**, regardless of how the loops are nested.

This pattern appears in many sliding window and monotonic stack problems. The key signal: **pointers only move in one direction**.
