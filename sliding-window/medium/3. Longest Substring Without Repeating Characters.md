[3. Longest Substring Without Repeating Characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/description/?envType=study-plan-v2&envId=top-interview-150) (Medium)
---

### Core Insight
Same **sliding window** pattern — but instead of tracking a sum, you track a **set of seen characters**. When you hit a duplicate, shrink from the left until it's gone.

---

### Solution

```csharp
public int LengthOfLongestSubstring(string s) {
    var seen = new HashSet<char>();
    int left = 0, maxLen = 0;

    for (int right = 0; right < s.Length; right++) {
        // shrink window until the duplicate is removed
        while (seen.Contains(s[right])) {
            seen.Remove(s[left]);
            left++;
        }

        seen.Add(s[right]);
        maxLen = Math.Max(maxLen, right - left + 1);
    }

    return maxLen;
}
```

### Why O(n)?

Same argument as before:
- `right` travels the string **exactly once** → n steps
- `left` can only move **forward, never backward** → at most n steps
- Each character is added to `seen` once and removed at most once
- **Total = 2n → O(n)**

---

### Optimized Version — O(n) with faster shrink

The `HashSet` version shrinks **one step at a time**. You can skip directly to the right position using a **Dictionary that stores the last seen index**:

```csharp
public int LengthOfLongestSubstring(string s) {
    var lastIndex = new Dictionary<char, int>();
    int left = 0, maxLen = 0;

    for (int right = 0; right < s.Length; right++) {
        // if duplicate exists AND it's inside current window → jump left past it
        if (lastIndex.TryGetValue(s[right], out int prevIdx) && prevIdx >= left) {
            left = prevIdx + 1;  // skip left directly, no while loop needed
        }

        lastIndex[s[right]] = right;  // update last seen position
        maxLen = Math.Max(maxLen, right - left + 1);
    }

    return maxLen;
}
```

**The key difference:**

| | HashSet version | Dictionary version |
|---|---|---|
| Duplicate handling | Shrink one char at a time (`while` loop) | Jump `left` directly to `prevIdx + 1` |
| Steps on `"bbbbb"` | left moves: 0→1→2→3→4 | left jumps: 0→1→2→3→4 (same count, but **no inner loop**) |
| Time complexity | O(n) — same | O(n) — same |
| In practice | Slightly more iterations | Cleaner, fewer operations |

> **Both are O(n).** The Dictionary version just eliminates the inner `while` by doing the math directly.

---

### Key Takeaways
- **Pattern match:** "longest/smallest window with a constraint" → sliding window
- **`HashSet`** = simpler to reason about, shrinks gradually
- **`Dictionary`** = stores last index, jumps `left` in one step — preferred in interviews
- The `prevIdx >= left` guard is **critical** — without it you might move `left` backwards when a character appeared before the current window
