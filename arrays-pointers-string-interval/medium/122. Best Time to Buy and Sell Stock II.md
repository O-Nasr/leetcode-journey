[122. Best Time to Buy and Sell Stock II](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/description/?envType=study-plan-v2&envId=top-interview-150) (Medium)
---
### Core Insight

You can trade unlimited times. The key realization:

> **Any upward slope = profit you can capture.**

You don't need to find the perfect buy/sell points. Just **collect every positive day-to-day difference**.

---

### The Analogy

Think of the price chart as a hiking trail with hills and valleys.

```
Price:  7   1   5   3   6   4
        ↓   ↑   ↑   ↓   ↑   ↓
       drop climb  drop climb drop
```

- You **only walk uphill segments** — those are your profits
- You **sit out every downhill** — no loss taken
- Holding overnight = just walking the slope one step at a time

**Greedy truth:** Capturing every `+1` step of a hill = capturing the entire hill.

```
Buy day2(1) → sell day3(5) = +4    ← one big step
  OR
Buy day2(1) → sell day3? No intermediate, but:
  day2→day3 = +4  (same result, just collected as one chunk)

For [1,2,3,4,5]:
  Collect: +1 +1 +1 +1 = 4  ← same as buy day1, sell day5
```

---

### Solution

```csharp
public int MaxProfit(int[] prices) {
    int profit = 0;

    for (int i = 1; i < prices.Length; i++) {
        // only grab the gain, ignore the loss
        if (prices[i] > prices[i - 1])
            profit += prices[i] - prices[i - 1];
    }

    return profit;
}
```

Or even more concise using `Math.Max`:

```csharp
public int MaxProfit(int[] prices) {
    int profit = 0;

    for (int i = 1; i < prices.Length; i++)
        profit += Math.Max(0, prices[i] - prices[i - 1]);

    return profit;
}
```

> **`Math.Max(0, diff)`** = "take the gain if positive, otherwise take nothing." One liner, same logic.

### Step-by-Step Trace

```
prices = [7, 1, 5, 3, 6, 4]
          d0  d1  d2  d3  d4  d5
```

| Step | i | prices[i-1] | prices[i] | diff | profit |
|------|---|-------------|-----------|------|--------|
| 1 | 1 | 7 | 1 | -6 | 0 (skip) |
| 2 | 2 | 1 | 5 | +4 | **4** |
| 3 | 3 | 5 | 3 | -2 | 4 (skip) |
| 4 | 4 | 3 | 6 | +3 | **7** |
| 5 | 5 | 6 | 4 | -2 | 7 (skip) |

**Answer: 7** ✓

### Why Greedy Works Here

The mathematical proof is simple. Any multi-day trade can be **decomposed into daily steps**:

```
Buy day 1 (price=1), Sell day 3 (price=5):
  profit = 5 - 1 = 4

Decomposed:
  day1→day2 = 5 - 1 = 4   ← same result

Buy day 1 (price=1), Sell day 5 (price=5) on [1,2,3,4,5]:
  profit = 5 - 1 = 4

Decomposed:
  (2-1) + (3-2) + (4-3) + (5-4) = 1+1+1+1 = 4  ← identical
```

> **Any long hold = sum of daily steps in that period.** So collecting every positive daily step = collecting every profitable long hold. You can't do better.

### Key Takeaways
- **No sliding window here** — this is a **greedy** problem
- The trick: realize `buy[i] → sell[j]` profit always equals the sum of daily gains between `i` and `j`
- **Never hold through a loss** — always skip negative differences
- `Math.Max(0, diff)` is the cleanest expression of "capture gains, skip losses"
- This greedy only works because **unlimited trades are allowed** — restricted trade count problems (LC 121, 123, 188) need DP instead
