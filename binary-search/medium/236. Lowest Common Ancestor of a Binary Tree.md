# Step 1: Understand the Problem

We need to find the **Lowest Common Ancestor (LCA)** of two nodes.

The LCA is:

> The **lowest node** that has **both p and q** somewhere in its subtree.

A node is also considered a descendant of itself.

For example:

```text
          3
        /   \
       5     1
      / \   / \
     6   2 0   8
        / \
       7   4
```

If

```text
p = 5
q = 1
```

Then

```text
LCA = 3
```

because 3 is the first node that contains both.

---

Another example

```text
          3
        /   \
       5     1
      / \
     6   2
        / \
       7   4
```

If

```text
p = 5
q = 4
```

Then

```text
LCA = 5
```

because a node can be its own ancestor.

---

# Step 2: Think Bottom-Up

Most people initially think:

> "Starting from the root, how do I find the LCA?"

That makes the problem difficult.

Instead think:

> **Each subtree should tell its parent whether it found p or q.**

So every recursive call answers only one question:

> **"Did I find p? Did I find q?"**

It returns:

* `null`
* `p`
* `q`
* or the LCA

---

# Step 3: What Should DFS Return?

Let's define:

```csharp
TreeNode DFS(TreeNode node)
```

What should it return?

It returns:

* `null` → neither p nor q exists here.
* `p` → found p.
* `q` → found q.
* LCA → already found the answer.

This is the whole idea.

---

# Step 4: Recursive Cases

At every node there are only four possibilities.

## Case 1

Current node is null.

```csharp
if (root == null)
    return null;
```

Nothing found.

---

## Case 2

Current node is p or q.

```csharp
if (root == p || root == q)
    return root;
```

Return it upward.

You're basically telling your parent:

> "I found one of the targets."

---

## Case 3

Search left and right.

```csharp
TreeNode left = LowestCommonAncestor(root.left, p, q);
TreeNode right = LowestCommonAncestor(root.right, p, q);
```

Now we inspect what they returned.

---

## Case 4

Both returned something.

```text
      root
      /  \
     p    q
```

That means

* left subtree found one target
* right subtree found the other

Therefore

```csharp
return root;
```

because this is the first node containing both.

---

## Case 5

Only one side found something.

Example

```text
left = p
right = null
```

Then simply return

```csharp
return left;
```

Likewise

```text
left = null
right = q
```

Return

```csharp
return right;
```

This propagates the found node upward.

# Step 6: C# Solution

```csharp
public class Solution
{
    public TreeNode LowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q)
    {
        // Base case: reached the end of a branch
        if (root == null)
            return null;

        // Found one of the target nodes
        if (root == p || root == q)
            return root;

        // Search in the left subtree
        TreeNode left = LowestCommonAncestor(root.left, p, q);

        // Search in the right subtree
        TreeNode right = LowestCommonAncestor(root.right, p, q);

        // If both sides found a target,
        // current node is the Lowest Common Ancestor.
        if (left != null && right != null)
            return root;

        // Otherwise return whichever side found something.
        return left ?? right;
    }
}
```

# Step 7: Explain the Code Line by Line

## Base Case

```csharp
if (root == null)
    return null;
```

You've reached beyond a leaf.

Nothing exists here.

---

## Found One Target

```csharp

    return root;
```

Suppose

```text
      5
     /
    4
```

Searching for

```text
p = 5
q = 4
```

When DFS reaches 5, it returns 5 immediately.

Why?

Because it tells its parent:

> "I found one of the targets."

---

## Search Left

```csharp
TreeNode left = LowestCommonAncestor(root.left, p, q);
```

This recursively asks

> "Does my left subtree contain p or q?"

---

## Search Right

```csharp
TreeNode right = LowestCommonAncestor(root.right, p, q);
```

Same question for the right subtree.

---

## Both Sides Found Something

```csharp
if (left != null && right != null)
    return root;
```

Imagine

```text
        A
      /   \
     B     C

p in B
q in C
```

Left returns

```text
p
```

Right returns

```text
q
```

The first node seeing both is

```text
A
```

So A is the LCA.

---

## Only One Side Found Something

```csharp
return left ?? right;
```

This means

```csharp
if (left != null)
    return left;

return right;
```

Possible outcomes:

| Left | Right | Return |
| ---- | ----- | ------ |
| null | null  | null   |
| p    | null  | p      |
| null | q     | q      |

Notice that the case where both are non-null was already handled.

# Step 8: Why Does This Work?

Each recursive call reports one of four states:

| Return Value | Meaning                             |
| ------------ | ----------------------------------- |
| `null`       | Neither p nor q found.              |
| `p`          | Found p only.                       |
| `q`          | Found q only.                       |
| `root` (LCA) | Both targets found in this subtree. |

The first node that receives a non-null value from **both** its left and right children is the **lowest** node that has both targets beneath it, making it the Lowest Common Ancestor.

# Interview Tips

1. **Recognize the pattern:** Many tree problems become simpler when you think **bottom-up**. Ask what information each recursive call should return to its parent, rather than trying to solve the entire problem at the root.

2. **Understand the return value:** The recursive function isn't always returning the final answer. Before the LCA is found, it returns `p` or `q` to signal that one target has been located. Only when a node sees one target from each side does it return the actual LCA.

3. **Don't compare node values:** The problem guarantees that `p` and `q` are actual nodes in the tree. Compare references (`root == p`), not values (`root.val == p.val`), even though the values are unique. Using node references is the intended and more robust approach.
