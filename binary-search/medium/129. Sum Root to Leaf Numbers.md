# 129. Sum Root to Leaf Numbers
**Difficulty**: Medium

**LeetCode Link**: [129. Sum Root to Leaf Numbers](https://leetcode.com/problems/sum-root-to-leaf-numbers/description/?envType=study-plan-v2&envId=top-interview-150)
---

This is a classic **DFS + Backtracking (state passing)** problem.

The trick is realizing that **you don't need to store the entire path**. You only need to carry the number formed so far.

---

# Key Observation

Suppose you're traversing the tree:

```text
    1
   / \
  2   3
```

The path

```text
1 -> 2
```

represents

```text
12
```

How do we build `12`?

Start with

```text
1
```

Visit `2`

```text
1 * 10 + 2 = 12
```

Similarly,

```text
1 -> 3

1 * 10 + 3 = 13
```

So every time we move down one level:

```text
currentNumber = currentNumber * 10 + node.val
```

That's the entire trick.

# Recursive Idea

For every node

```
current = current * 10 + node.val
```

If it's a leaf

```
return current
```

Otherwise

```
return
leftSum + rightSum
```

Notice that each subtree returns the total of all numbers beneath it.

# C# Solution

```csharp
public class Solution
{
    public int SumNumbers(TreeNode root)
    {
        return DFS(root, 0);
    }

    private int DFS(TreeNode node, int current)
    {
        if (node == null)
            return 0;

        current = current * 10 + node.val;

        // Leaf node
        if (node.left == null && node.right == null)
            return current;

        return DFS(node.left, current)
             + DFS(node.right, current);
    }
}
```

---

# Why Don't We Need to "Undo" (`current /= 10`)?

Many DFS/backtracking problems require restoring state after recursion.

For example:

```csharp
path.Add(node.val);

DFS(left);

path.RemoveAt(path.Count - 1);
```

Here, **`current` is an `int` passed by value**.

Suppose

```
current = 49
```

Call

```csharp
DFS(left, current);
```

Inside the recursive call, it becomes

```
495
```

When that call returns, the caller's `current` is still

```
49
```

because integers in C# are copied when passed as parameters.

So there's nothing to undo.

# Alternative Solution Using a Global Sum

Some people prefer:

```csharp
int sum = 0;

void DFS(...)
```

```csharp
public class Solution
{
    private int sum = 0;

    public int SumNumbers(TreeNode root)
    {
        DFS(root, 0);
        return sum;
    }

    private void DFS(TreeNode node, int current)
    {
        if (node == null)
            return;

        current = current * 10 + node.val;

        if (node.left == null && node.right == null)
        {
            sum += current;
            return;
        }

        DFS(node.left, current);
        DFS(node.right, current);
    }
}
```

This works, but the previous version is generally cleaner because each recursive call simply returns its contribution instead of relying on shared state.

# Complexity

Let:

* **n** = number of nodes
* **h** = tree height

### Time

Every node is visited once.

```
O(n)
```

### Space

The recursion stack stores at most one path from the root to a leaf.

```
O(h)
```

Worst case (skewed tree):

```
O(n)
```

Balanced tree:

```
O(log n)
```

# Interview Takeaways

The interviewer is looking for these insights:

1. A root-to-leaf path represents a number built digit by digit.

2. You can update the current number incrementally with:

   ```
   current = current * 10 + node.val
   ```

3. When you reach a leaf, that `current` value is a complete number and should be returned (or added to the total).

4. Since `current` is passed by value in C#, no explicit backtracking is needed. Each recursive call works with its own copy of the accumulated number.
