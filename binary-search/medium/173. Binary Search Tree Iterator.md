# 173. Binary Search Tree Iterator
**Difficulty**: Medium

**LeetCode Link**: [173. Binary Search Tree Iterator](https://leetcode.com/problems/binary-search-tree-iterator/description/?envType=study-plan-v2&envId=top-interview-150)
---

This is an excellent interview question because it tests whether you understand **in-order traversal** and how to **convert recursion into an iterative solution using a stack**.

The follow-up (**O(1) average time and O(h) space**) is the expected solution.

---

# Step 1: Understand the Problem

We're asked to implement an **iterator** over a BST.

For the BST

```text
        7
      /   \
     3     15
          /  \
         9   20
```

An **in-order traversal** visits nodes in this order:

```text
3 → 7 → 9 → 15 → 20
```

The iterator should behave like this:

```csharp
BSTIterator iterator = new BSTIterator(root);

iterator.next();     // 3
iterator.next();     // 7
iterator.hasNext();  // true
iterator.next();     // 9
iterator.next();     // 15
iterator.next();     // 20
iterator.hasNext();  // false
```

Notice that we're **not returning the whole traversal at once**.

Instead, we return **one node at a time**, just like `IEnumerator<T>` in C#.

---

# Step 2: First (Naive) Solution

One simple idea is:

1. Perform an in-order traversal.
2. Store every value in a list.
3. Keep an index.

Example:

```text
BST

       7
      / \
     3  15
       /  \
      9   20
```

Store

```text
[3,7,9,15,20]
```

Then

```csharp
next()
```

simply returns

```csharp
list[index++]
```

### Complexity

Constructor:

```text
O(n)
```

Memory:

```text
O(n)
```

This works, but the follow-up specifically asks for **O(h)** memory, so we need a better solution.

# Step 3: Key Observation

How does recursive in-order traversal work?

```csharp
InOrder(node)
{
    InOrder(node.left);

    Visit(node);

    InOrder(node.right);
}
```

The recursion stack remembers:

> "Which parent should I return to after finishing the left subtree?"

We can replace that recursion stack with our own **Stack<TreeNode>**.

---

# Step 4: The Big Idea

Stack:

```text

```

Notice the top is always the next smallest element.

# Step 7: Why Push the Leftmost Path?

Suppose we have

```text
      20
     /
   15
   /
 10
```

The next node isn't 20.

It isn't 15.

It is

```text
10
```

So whenever we move to a subtree, we always push **all left children**.

That guarantees the stack's top is always the next smallest element.

---

# Step 8: C# Solution (Best)

```csharp
public class BSTIterator
{
    private Stack<TreeNode> stack = new Stack<TreeNode>();

    public BSTIterator(TreeNode root)
    {
        PushLeft(root);
    }

    public int Next()
    {
        // The top of the stack is the next smallest node.
        TreeNode node = stack.Pop();

        // If the node has a right subtree,
        // push its leftmost path.
        if (node.right != null)
        {
            PushLeft(node.right);
        }

        return node.val;
    }

    public bool HasNext()
    {
        return stack.Count > 0;
    }

    private void PushLeft(TreeNode node)
    {
        while (node != null)
        {
            stack.Push(node);
            node = node.left;
        }
    }
}
```
# Another Solution:

```csharp
public class BSTIterator {

private readonly List<int> _inOrderList;
    private int _index = -1;
    public BSTIterator(TreeNode root)
    {
        _inOrderList = new List<int>();
        InOrder(root);
    }
    
    public int Next()
    {
        _index++;
        return _inOrderList[_index];
    }
    
    public bool HasNext() {
        return (_index + 1) < _inOrderList.Count;
    }

    private void InOrder(TreeNode? root)
    {
        if(root == null) return;
        InOrder(root.left);
        _inOrderList.Add(root.val);
        InOrder(root.right);
    }
}
```

# Step 9: Explain the Code Line by Line

## Stack

```csharp
private Stack<TreeNode> stack = new Stack<TreeNode>();
```

This replaces the recursion stack used by recursive in-order traversal.

It stores the path to the next node that should be visited.

---

## Constructor

```csharp
PushLeft(root);
```

We don't traverse the whole tree.

We only push the leftmost path.

Example:

```text
      7
     /
    3
```

Stack becomes

```text
Top
---
3
7
```

The smallest element is now on top.

---

## PushLeft()

```csharp
private void PushLeft(TreeNode node)
{
    while (node != null)
    {
        stack.Push(node);
        node = node.left;
    }
}
```

This helper walks down a subtree, pushing every left child.

Example:

```text
        15
       /
      9
     /
    8
```

After `PushLeft(15)`:

```text
Top
---
8
9
15
```

The smallest node in that subtree is ready to be returned next.

---

## Next()

```csharp
TreeNode node = stack.Pop();
```

The top of the stack is always the next node in in-order traversal.

---

### If there's a right subtree

```csharp
if (node.right != null)
{
    PushLeft(node.right);
}
```

After visiting a node, in-order traversal moves to its right subtree.

However, it doesn't visit the right child immediately—it first visits the leftmost node within that right subtree. `PushLeft()` prepares the stack for those future visits.

---

## HasNext()

```csharp
return stack.Count > 0;
```

If the stack still contains nodes, there are more values to return.

# Step 10: Why is the Average Time O(1)?

At first glance, `PushLeft()` looks like it could take **O(h)** time.

For example:

```text
20
/
15
/
10
/
5
```

Pushing that path takes `O(h)`.

However, here's the important observation:

* Every node is **pushed exactly once**.
* Every node is **popped exactly once**.

Across the entire iteration:

* Total pushes = `n`
* Total pops = `n`

So the total work is `2n`, which is `O(n)`.

Since there are `n` calls to `Next()`, the **amortized (average) cost per call** is:

```text
O(n) / n = O(1)
```

This is why the follow-up specifies **average O(1)** rather than worst-case O(1).

---

# Step 11: Complexity Analysis

### Constructor

* **Time:** `O(h)` (pushes the leftmost path)
* **Space:** `O(h)` (stack holds at most one root-to-leaf path)

### `Next()`

* **Worst-case Time:** `O(h)` (if it has to push a long left path)
* **Average (Amortized) Time:** `O(1)`

### `HasNext()`

* **Time:** `O(1)`

### Overall Space

```text
O(h)
```

where `h` is the height of the tree.

* Balanced BST: `O(log n)`
* Skewed BST: `O(n)`

# Interview Tips

1. **Recognize the pattern:** When asked to implement an iterator for a tree, think about replacing **recursive DFS with an explicit stack**.

2. **Know the in-order property of a BST:** In-order traversal of a BST always produces values in **sorted ascending order**, which is why this iterator naturally returns elements from smallest to largest.

3. **Understand amortized analysis:** Even though a single call to `Next()` can take `O(h)` time, every node is pushed and popped exactly once. This is a classic example of **amortized O(1)** performance.
