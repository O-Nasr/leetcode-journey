# 106. Construct Binary Tree from Inorder and Postorder Traversal
**Difficulty**: Medium

**LeetCode Link**: [106. Construct Binary Tree from Inorder and Postorder Traversal](https://leetcode.com/problems/construct-binary-tree-from-inorder-and-postorder-traversal/description/?envType=study-plan-v2&envId=top-interview-150)
---

This problem is the **mirror image** of LeetCode **105**. If you understood 105, then 106 becomes much easier.

The only difference is:

* **105:** Preorder → **Root, Left, Right**
* **106:** Postorder → **Left, Right, Root**

The inorder traversal is the same:

* **Inorder:** **Left, Root, Right**

So instead of taking the **first** element as the root, we now take the **last**.

---

# Step 1: Understand the Traversals

Consider the tree

```text
        3
       / \
      9   20
         /  \
        15   7
```

### Inorder

```
9 3 15 20 7
```

### Postorder

```
9 15 7 20 3
```

Notice

```
Last element = Root
```

So

```
root = 3
```

---

# Step 2: Split Using Inorder

Locate `3` inside inorder.

```
9 | 3 | 15 20 7
```

Immediately we know

```
Left subtree

9

Right subtree

15 20 7
```

Exactly the same idea as problem 105.

---

# Step 3: The Important Difference

In problem 105 we had

```
Root Left Right
```

So after the root came the left subtree.

Now we have

```
Left Right Root
```

The root is at the end.

Remove it.

```
9 15 7 20 | 3
```

Now notice something important.

The element immediately before the root is

```
20
```

which is **the root of the right subtree**, **not** the left subtree.

This is the biggest trick in the problem.

---

# Why Build the Right Subtree First?

Suppose

```
postorder

9 15 7 20 3
           ^
        postRight
```

We choose

```
3
```

as the root.

Now

```
20
```

is immediately before it.

That belongs to the **right subtree**.

If we tried building the left subtree first, we'd accidentally consume nodes that actually belong to the right subtree.

Therefore, **when consuming postorder from the end, we must build the right subtree before the left subtree.**

# Recursive Idea

Each recursive call receives

```
Build(
    inLeft,
    inRight,
    postLeft,
    postRight
)
```

Steps

```
1. Root = postorder[postRight]

2. Find root in inorder

3. Compute left subtree size

4. Build RIGHT subtree

5. Build LEFT subtree
```

Notice the reversed order.

---

# Why Does the Right Subtree Come First?

Suppose

```
Postorder

9 15 7 20 3
```

Working backwards

```
3
20
7
15
9
```

The sequence becomes

```
Root
Right
Left
```

So recursion must follow that same order.

This is the key insight interviewers are looking for.

---

# Index Calculations

Suppose

```
rootIndex = inorder index

leftSize = rootIndex - inLeft

rightSize = inRight - rootIndex
```

Left subtree

```
postLeft

to

postLeft + leftSize - 1
```

Right subtree

```
postLeft + leftSize

to

postRight - 1
```

Notice

The right subtree ends just before the root.

# C# Solution (Optimal)

```csharp
public class Solution
{
    private Dictionary<int, int> inorderIndex;

    public TreeNode BuildTree(int[] inorder, int[] postorder)
    {
        inorderIndex = new Dictionary<int, int>();

        for (int i = 0; i < inorder.Length; i++)
            inorderIndex[inorder[i]] = i;

        return Build(
            inorder, 0, inorder.Length - 1,
            postorder, 0, postorder.Length - 1);
    }

    private TreeNode Build(
        int[] inorder,
        int inLeft,
        int inRight,
        int[] postorder,
        int postLeft,
        int postRight)
    {
        if (inLeft > inRight)
            return null;

        int rootValue = postorder[postRight];
        TreeNode root = new TreeNode(rootValue);

        int rootIndex = inorderIndex[rootValue];

        int leftSize = rootIndex - inLeft;

        root.left = Build(
            inorder,
            inLeft,
            rootIndex - 1,
            postorder,
            postLeft,
            postLeft + leftSize - 1);

        root.right = Build(
            inorder,
            rootIndex + 1,
            inRight,
            postorder,
            postLeft + leftSize,
            postRight - 1);

        return root;
    }
}
```

You may notice that the code assigns `root.left` before `root.right`. **This is perfectly correct** because each recursive call receives explicit index ranges. The important part is not the assignment order—it's that the calculated ranges correctly identify the left and right subtree segments in the arrays.

# An Alternative Implementation (Often Seen in Interviews)

Many interviewers prefer a slightly different approach that keeps a **single global index** into the postorder array, starting at the end.

```csharp
int postIndex = postorder.Length - 1;

TreeNode Build(int left, int right)
{
    if (left > right)
        return null;

    int value = postorder[postIndex--];
    TreeNode root = new TreeNode(value);

    int mid = inorderIndex[value];

    // Must build right first!
    root.right = Build(mid + 1, right);
    root.left = Build(left, mid - 1);

    return root;
}
```

Here, building the **right subtree first is mandatory** because `postIndex` moves backward through the array:

```
Postorder:
9 15 7 20 3

Reading backwards:
3 → 20 → 7 → 15 → 9

Root → Right → Left
```

If you built the left subtree first with a shared `postIndex`, you would consume nodes that actually belong to the right subtree.

---

# Complexity

Using the hash map:

* **Time:** **O(n)** — every node is processed once.
* **Space:** **O(n)** — hash map plus recursion stack (up to O(n) in the worst case).

---

# Comparing Problems 105 and 106

| Problem                       | Root comes from       | Next subtree to process (shared-index approach) |
| ----------------------------- | --------------------- | ----------------------------------------------- |
| **105 (Preorder + Inorder)**  | Beginning of preorder | Left subtree first                              |
| **106 (Inorder + Postorder)** | End of postorder      | Right subtree first                             |

The underlying strategy is identical:

1. Use one traversal to identify the root.
2. Use inorder to split left and right subtrees.
3. Recurse on the resulting segments.

The only conceptual change is **where the root appears** and, in the shared-index implementation, **which subtree you must construct first**.
