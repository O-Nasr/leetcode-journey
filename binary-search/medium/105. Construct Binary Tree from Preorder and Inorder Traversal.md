# 105. Construct Binary Tree from Preorder and Inorder Traversal
**Difficulty**: Medium

**LeetCode Link**: [105. Construct Binary Tree from Preorder and Inorder Traversal](https://leetcode.com/problems/construct-binary-tree-from-preorder-and-inorder-traversal/description/?envType=study-plan-v2&envId=top-interview-150)
---

This is one of the most important binary tree interview problems. The interviewer wants to know whether you truly understand **tree traversals** and can use their properties to reconstruct a tree.

The trick is to combine what each traversal tells you:

* **Preorder = Root → Left → Right**
* **Inorder = Left → Root → Right**

The preorder traversal tells you **who the root is**, while the inorder traversal tells you **where to split the tree into left and right subtrees**.

---

# Step 1: Understand the Traversals

Suppose we have

```text
        3
       / \
      9   20
         /  \
        15   7
```

### Preorder (Root → Left → Right)

```
3 9 20 15 7
```

Notice the first element is always the root.

---

### Inorder (Left → Root → Right)

```
9 3 15 20 7
```

Everything before `3` belongs to the left subtree.

Everything after `3` belongs to the right subtree.

---

# Step 2: The Main Observation

Suppose

```
preorder = [3,9,20,15,7]

inorder  = [9,3,15,20,7]
```

The first preorder element is

```
3
```

So

```
root = 3
```

Now find `3` in inorder.

```
9 | 3 | 15 20 7
```

Immediately we know

```
Left subtree:
9

Right subtree:
15 20 7
```

---

# Step 3: How do we know the preorder of each subtree?

Preorder visits

```
Root
Left subtree
Right subtree
```

We've already consumed the root (`3`).

The next preorder elements must belong to the left subtree.

How many?

Exactly the size of the left subtree.

From inorder

```
Left subtree contains

[9]

size = 1
```

Therefore

```
preorder

3 | 9 | 20 15 7
    ^
 left subtree
```

So

Left preorder

```
[9]
```

Right preorder

```
[20,15,7]
```

Now recursively solve both.

# Recursive Idea

Each recursive call receives the portion of the arrays representing one subtree.

```
Build(preLeft, preRight,
      inLeft, inRight)
```

Steps

```
1. Root = preorder[preLeft]

2. Find root in inorder

3. Compute left subtree size

4. Recursively build left

5. Recursively build right
```

---

# Naive Solution (O(n²))

If we search for the root in inorder every time,

```
find(root)
```

takes O(n).

Doing this for every node gives

```
O(n²)
```

Too slow for n = 3000.

---

# Optimization

Create a dictionary

```csharp
Dictionary<int,int>
```

mapping

```
value -> inorder index
```

Example

```
9  -> 0

3  -> 1

15 -> 2

20 -> 3

7  -> 4
```

Now finding the root in inorder is

```
O(1)
```

Overall complexity becomes

```
O(n)
```

---

# C# Solution (Optimal)

```csharp
public class Solution
{
    private Dictionary<int, int> inorderIndex;
    public TreeNode BuildTree(int[] preorder, int[] inorder)
    {
        if(preorder.Length == 0) return null;
        if(preorder.Length == 1) return new TreeNode(preorder[0]);
        
        TreeNode root = new TreeNode(preorder[0]);
        
        inorderIndex  = new Dictionary<int, int>(inorder.Length);
        
        for (int i = 0; i < inorder.Length; i++) 
        {
            inorderIndex .Add(inorder[i], i);
        }
        
        return BuildTreeHelper(preorder, 0, preorder.Length - 1,0);
    }

    private TreeNode BuildTreeHelper(int[] preorder, int preLeft, int preRight, int inLeft)
    {
        if (preLeft > preRight)
            return null;
        int rootVal = preorder[preLeft];
        TreeNode root = new TreeNode(rootVal);
        
        int rootIndex = inorderIndex[rootVal];
        int leftLenght = rootIndex - inLeft;
        
        root.left = BuildTreeHelper(preorder, 
            preLeft + 1,
            preLeft + leftLenght,
            inLeft);
        root.right = BuildTreeHelper(preorder, 
            preLeft + leftLenght + 1, 
            preRight,
            rootIndex + 1);
        
        return root;
    }
}
```

# Why Doesn't the Right Subtree Size Need to Be Calculated?

Once you know the size of the left subtree, the remaining preorder elements (after the root and left subtree) must belong to the right subtree. That's why you only need to calculate `leftSize`; the right subtree boundaries follow automatically from the existing `preRight` and `inRight` limits.

---

# Complexity Analysis

Using the hash map:

* **Time:** **O(n)** — each node is created once, and each inorder lookup is O(1).
* **Space:** **O(n)** — for the hash map plus the recursion stack (O(h), up to O(n) in the worst case).

---

# Interview Takeaways

The interviewer is looking for these insights:

1. **Preorder always gives you the root first.**
2. **Inorder tells you how to split the tree into left and right subtrees.**
3. **The size of the left subtree (from inorder) tells you exactly how to partition the preorder array.**
4. **Using a hash map for inorder indices reduces the solution from O(n²) to O(n).**

Once you internalize those four ideas, this pattern becomes reusable for many tree-construction problems.
