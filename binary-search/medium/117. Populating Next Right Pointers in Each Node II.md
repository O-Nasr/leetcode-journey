# 117. Populating Next Right Pointers in Each Node II
**Difficulty**: Medium

**LeetCode Link**: [117. Populating Next Right Pointers in Each Node II](https://leetcode.com/problems/populating-next-right-pointers-in-each-node-ii/description/?envType=study-plan-v2&envId=top-interview-150)
---

This problem is a follow-up to **116. Populating Next Right Pointers in Each Node**.

The difference is very important:

* **116:** The tree is **perfect** (every internal node has exactly 2 children, and all leaves are on the same level).
* **117:** The tree can be **any binary tree**.

That means we can no longer rely on `left` and `right` always existing.

---

# Problem

For every node, set

```text
node.next
```

to the node immediately to its right on the same level.

Example

```text
        1
      /   \
     2     3
    / \     \
   4   5     7
```

Should become

```text
        1 -> null
      /   \
     2 --> 3 -> null
    / \     \
   4->5-->7->null
```

---

# Solution 1 — Level Order Traversal (BFS)

The easiest solution.

Use a queue.

For each level:

* remember the previous node
* connect it to the current node

---

## Example

Queue

```text
1
```

Process level

```
1 -> null
```

Queue becomes

```
2 3
```

Next level

```
2 -> 3 -> null
```

Queue becomes

```
4 5 7
```

Next level

```
4 -> 5 -> 7 -> null
```

Done.

---

## C#

```csharp
public class Solution
{
    public Node Connect(Node root)
    {
        if (root == null)
            return null;

        Queue<Node> queue = new Queue<Node>();
        queue.Enqueue(root);

        while (queue.Count > 0)
        {
            int size = queue.Count;
            Node prev = null;

            for (int i = 0; i < size; i++)
            {
                Node curr = queue.Dequeue();

                if (prev != null)
                    prev.next = curr;

                prev = curr;

                if (curr.left != null)
                    queue.Enqueue(curr.left);

                if (curr.right != null)
                    queue.Enqueue(curr.right);
            }
        }

        return root;
    }
}
```

# Follow-up: Constant Extra Space

This is the interesting part.

Instead of using a queue,

we use the **next pointers that we are building**.

Think of it as creating a linked list for each level.

---

## Main Idea

Suppose we already have

```text
Level 1

2 -> 3 -> null
```

Instead of storing nodes in a queue,

we can simply walk

```text
2

then

3
```

using

```text
current = current.next
```

While walking across the current level,

we simultaneously build the next level.

# Three Pointers

We maintain

### current

Current node on the current level.

```text

^
```

---

### dummy

A fake node.

It marks the beginning of the next level.

```text
dummy
```

---

### tail

Always points to the last connected node.

Initially

```text

 ^
tail
```

When we see

```

```

          ^
        tail

```

             tail
```

Then

```

```

```

                    ^
                  tail
```

At the end

```

```

Now we start processing

# Constant Space C#

```csharp
public class Solution
{
    public Node Connect(Node root)
    {
        Node current = root;

        while (current != null)
        {
            Node dummy = new Node(0);
            Node tail = dummy;

            while (current != null)
            {
                if (current.left != null)
                {
                    tail.next = current.left;
                    tail = tail.next;
                }

                if (current.right != null)
                {
                    tail.next = current.right;
                    tail = tail.next;
                }

                current = current.next;
            }

            current = dummy.next;
        }

        return root;
    }
}
```

---

# Why does this use O(1) space?

Many people initially think:

> "We're creating a new `dummy` node every level, so isn't that O(n)?"

No. At any point in time, you only have:

* one `current` pointer
* one `tail` pointer
* one `dummy` node

Even though a new dummy node is created for each level, the previous one becomes unreachable and is eligible for garbage collection. The amount of **simultaneously used** extra memory never grows with the number of nodes.

So the extra space is **O(1)**.

---

# Complexity

### BFS

* Time: **O(n)**
* Space: **O(n)**

### Constant-space solution

* Time: **O(n)** — every node is visited once.
* Extra space: **O(1)** — only a few pointers are used, regardless of the tree size.

# Interview Takeaways

The interviewer typically expects this progression:

1. Start with the straightforward **BFS using a queue**.
2. Recognize that the follow-up asks for **constant extra space**.
3. Observe that the `next` pointers you're building can also serve as the traversal mechanism for each level.
4. Use three pointers:

   * `current` to traverse the current level,
   * `dummy` to mark the start of the next level,
   * `tail` to build the linked list of the next level.

This "dummy + tail" pattern is a useful technique that appears in other linked-list and tree problems as well.
