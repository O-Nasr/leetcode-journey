# 73. Set Matrix Zeroes
**Difficulty**: medium

**LeetCode Link**: [73. Set Matrix Zeroes](https://leetcode.com/problems/set-matrix-zeroes/description/?envType=study-plan-v2&envId=top-interview-150) (Medium)
---
This is one of the most famous **in-place matrix** interview problems because it gradually pushes you from a straightforward solution to a clever constant-space solution.

Let's build it step by step.

---

# Step 1: Understand the Problem

Given:

```text
1 1 1
1 0 1
1 1 1
```

The `0` means:

* zero the entire row
* zero the entire column

Result:

```text
1 0 1
0 0 0
1 0 1
```

---

# Why is it tricky?

Suppose you start modifying immediately.

Example:

```text
1 1 1
1 0 1
1 1 1
```

You find the middle zero.

You immediately change its row:

```text
1 1 1
0 0 0
1 1 1
```

Now there are **new zeros** that didn't exist originally.

If you continue scanning, you'll mistakenly think those new zeros also require their rows and columns to be zeroed.

Eventually everything becomes zero.

So:

> **You cannot modify while you're still discovering original zeros.**

---

# Solution 1 — O(m × n) Extra Space

Create another matrix:

```text
mark[i][j]
```

Mark every cell that should become zero.

After the scan, copy back.

Works.

Not interview-worthy.

---

# Solution 2 — O(m + n)

Instead of another matrix:

Store which rows and columns should become zero.

```csharp
bool[] zeroRow = new bool[m];
bool[] zeroCol = new bool[n];
```

First pass:

```text
Find every zero.

If matrix[i][j]==0

zeroRow[i]=true
zeroCol[j]=true
```

Second pass:

```text
If row marked
or
column marked

→ set zero
```

Complexity:

Time:

```text
O(mn)
```

Space:

```text
O(m+n)
```

Much better.

---

# Follow-up: O(1) Space

This is the clever part.

Ask yourself:

> Where can I store the row and column markers?

The matrix already has:

* first row
* first column

Use them!

---

# Idea

Instead of

```text
zeroRow[]
zeroCol[]
```

store the information inside the matrix.

Example:

```text
1 1 1
1 0 1
1 1 1
```

When finding

```text
matrix[1][1]=0
```

Mark

```text
matrix[1][0]=0
```

meaning:

```text
Row 1 should become zero
```

Also

```text
matrix[0][1]=0
```

meaning:

```text
Column 1 should become zero
```

Now matrix becomes

```text
1 0 1
0 0 1
1 1 1
```

Notice:

The first row and first column are no longer data.

They're markers.

---

# Problem

What if the first row originally contained a zero?

Example:

```text
0 2 3
4 5 6
```

Now

```text
matrix[0][0]
```

has two meanings:

* first row marker
* first column marker

Impossible to distinguish.

---

# Solution

Keep two variables.

```csharp
bool firstRowZero
bool firstColZero
```

Before using the first row/column as markers:

Check whether they originally contained zeros.

---

# Algorithm

## Pass 1

Check:

```text
Does first row contain zero?
```

Store:

```csharp
firstRowZero
```

Check:

```text
Does first column contain zero?
```

Store:

```csharp
firstColZero
```

---

## Pass 2

Visit every cell **except** the first row and first column.

If:

```csharp
matrix[i][j]==0
```

Mark:

```csharp
matrix[i][0]=0;
matrix[0][j]=0;
```

---

## Pass 3

Again skip first row/column.

For every cell:

```csharp
if(matrix[i][0]==0 || matrix[0][j]==0)
    matrix[i][j]=0;
```

---

## Pass 4

If

```csharp
firstRowZero
```

Zero the first row.

If

```csharp
firstColZero
```

Zero the first column.

Done.

---

# Why the Order Matters

This order is crucial:

1. Save whether the first row/column originally had zeros.
2. Use the first row/column as markers.
3. Zero the inner matrix.
4. Finally, zero the first row/column if needed.

If you zero the first row too early, you destroy the marker information before you've used it.

---

# C# Implementation

```csharp
public void SetZeroes(int[][] matrix)
{
    int m = matrix.Length;
    int n = matrix[0].Length;

    bool firstRowZero = false;
    bool firstColZero = false;

    // Check first row
    for (int j = 0; j < n; j++)
    {
        if (matrix[0][j] == 0)
        {
            firstRowZero = true;
            break;
        }
    }

    // Check first column
    for (int i = 0; i < m; i++)
    {
        if (matrix[i][0] == 0)
        {
            firstColZero = true;
            break;
        }
    }

    // Mark rows and columns
    for (int i = 1; i < m; i++)
    {
        for (int j = 1; j < n; j++)
        {
            if (matrix[i][j] == 0)
            {
                matrix[i][0] = 0;
                matrix[0][j] = 0;
            }
        }
    }

    // Zero inner matrix
    for (int i = 1; i < m; i++)
    {
        for (int j = 1; j < n; j++)
        {
            if (matrix[i][0] == 0 || matrix[0][j] == 0)
            {
                matrix[i][j] = 0;
            }
        }
    }

    // Zero first row
    if (firstRowZero)
    {
        for (int j = 0; j < n; j++)
            matrix[0][j] = 0;
    }

    // Zero first column
    if (firstColZero)
    {
        for (int i = 0; i < m; i++)
            matrix[i][0] = 0;
    }
}
```

---

# Complexity

* **Time:** `O(m × n)` — every cell is visited a constant number of times.
* **Space:** `O(1)` — only two boolean variables are used besides the input matrix.

---

# Interview Pattern

This problem teaches a broader interview technique:

> **When asked for an in-place, constant-space solution, look for unused or repurposable space inside the input itself.**

Other problems use similar ideas:

* Rotate Image → reuse the matrix by transforming it in place.
* Game of Life → encode both old and new states in the same cell.
* Set Matrix Zeroes → use the first row and first column as marker arrays.

Recognizing when the input itself can act as auxiliary storage is a hallmark of strong interview problem solving.
